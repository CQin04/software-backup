# Everything MCP 配置修正与验证

日期：2026-10-23。范围：本机stdio MCP、ES命令行、Codex配置及可复用备份。上游MCP源码未改动，Everything主程序及安装包未修改。

## 版本

Everything 1.4.1.1032 x64；ES 1.1.1.39 x64；everything-mcp 1.0.9；Python 3.12.14；MCP SDK 2.3.0。依赖版本在 `requirements.lock.txt` 中固定。

## 中文路径问题

最初能找到文件，但ES在输出重定向时返回Windows系统代码页（实测ACP936）的字节；原配置 `PYTHONUTF8=1` 又使上游的系统编码回退变成UTF-8。于是查询本身成功，返回的中文路径却被替换字符破坏，元数据读取也可能失败。

修正配置：

```toml
PYTHONUTF8 = '0'
PYTHONIOENCODING = 'utf-8'
```

这样保留ES输出的系统编码回退，同时MCP标准输入输出仍为UTF-8。没有替换上游解码函数或改写软件二进制。

## 验证过程与最终结果

早期检查只验证命中数量和文件名，未验证返回的完整中文路径，因而未发现乱码。随后通过真实客户端调用发现问题，补充了“结果不得含Unicode替换字符”和“返回完整中文路径必须与真实文件一致”的检查，先复现失败，再验证修正后通过。

旧客户端连接没有随配置变化自动刷新，仅停止子进程也未自动重连。用户再次重启Codex后，本聊天通过原生MCP工具直接复测，最终五个工具全部成功：

| 工具 | 已验证行为 |
| --- | --- |
| 文件搜索 | 中文目录的3个工程文件，完整路径及大小、日期均正常 |
| 按类型搜索 | 受限目录中的压缩包 |
| 最近文件 | 受限目录中的近期Markdown文件 |
| 文件详情 | 正确中文路径、文件大小等元数据；正文预览关闭 |
| 统计 | 上述工程文件计数3，返回总大小 |

本机独立协议检查也通过了6项。供恢复使用的 `verify-mcp.py` 另外只生成公开测试内容的临时中文文件，验证工具发现、搜索、类型、近期、元数据和统计，避免依赖上传者的私人目录。
